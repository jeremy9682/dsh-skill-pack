# $full-throttle — 显式升档(蒸馏自 2026-07 提示词分析 T1/T3,历史手打 12+ 次)

被 `$full-throttle` 显式调用时执行本协议。**模糊口语("拉满"/"加大力度")不构成本协议授权**——那种情况只建议用户显式调用本 skill,不自行升档。

## 升档语义(只动执行侧,不碰终审席)

1. **推理深度**:若当前会话 reasoning effort 已是 xhigh,直接按最深模式执行(更多备选方案、更多自我验证、显式列取舍)。若低于 xhigh:提示用户切换(TUI 内 `/model`,或重跑时加**执行档显式覆盖** `-c model_reasoning_effort=xhigh`),并在等待期间仍按"深推理心智"执行,不假装档位已变。**绝不借用 `-p review` / `-p review-x`**——那是终审席 profile(只读),执行升档与终审升档是两回事。
2. **多 agent/后台并行**:允许 spawn 子 agent 与后台任务,但**每次 spawn 必须显式传 model / reasoning_effort / fork_turns**,严禁静默继承父会话档位(实测教训:静默继承 ultra + fork_turns=all 曾单日打爆 5h 额度)。机械子任务传低档,只有验证/终审传高档。
3. **档位事实源**:执行/终审分档遵循项目的档位路由配置(共享 canon),本文件不复制映射;终审侧地板与升档条件以 gate-policy 为准。

## `$full-throttle fable` — 跨家族盲审包

产出完成后,生成一份**盲审包**(自包含,不需要本会话上下文;**不含本席结论、评分或倾向**——含结论会锚定对方,不满足判断型/禁区的跨家族盲审要求):
- 材料路径(文件/diff 位置)+ 任务目标与约束(intent 三要素,措辞中立)
- 需要对方独立裁决的具体问题(≤5 条,可回答式,不预置答案)

流程硬约束:
1. **先写 checkpoint 事件并认领**:跨席交接前登记 checkpoint 事件(记录目标 repo 的标识,含盲审包路径),接手席动工前必须先认领该事件。
2. 盲审包写入工作目录 `crossreview-<任务slug>-<UTC时间戳,如 20260714T1030Z>.md`;**若目标文件已存在则换名,不得覆盖**。
3. 告知用户投给独立审阅席(跨家族盲审入口)。收到意见后:逐条 accept/challenge,综合后再呈报,不直传对方原文。
4. 若确需"带结论的讨论"(非盲),必须显式声明**该轮不构成终审**,终审另跑盲审。

## 不授予

本协议不授予:不可逆操作(push/deploy/删数据)、绕过 ship gate、启动 high-cost workflow(swarm/overnight 等)。那些仍走各自的批准流程。
